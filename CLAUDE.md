# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Satzspiegel: a Markdown stylesheet set to a book standard, derived from the 2025/2026 book, type and web design awards, with a Pandoc integration and self-hosted OFL typefaces. Intended to be published as the public GitHub repository `yobu/satzspiegel` with GitHub Pages serving the root.

| Path | Role |
|---|---|
| `satzspiegel.css` | Required. Tokens for two themes (Patina on bare `.md`, Archive on `.md[data-md-theme="archive"]`), the component layer, the theme layouts. Does not import `fonts.css`; the template links it (variable `fonts-css`), so `nofonts` can drop it. |
| `satzspiegel-code.css` | Optional code module. Class maps for Pandoc's skylighting, Prism, highlight.js and Shiki's css-variables theme. |
| `fonts.css`, `fonts/` | `@font-face` rules and WOFF2 Latin and Latin Extended subsets, generated by `scripts/fetch-fonts.mjs`; one `OFL.txt` per family. Never edit by hand. Google writes each subset label as a comment before its `@font-face` block; the script pairs them that way and refuses a `latin` face without the basic Latin range. `fonts.css` is linked by the template (variable `fonts-css`), not imported by the stylesheet, so `nofonts` can drop it; the `nocolophon` variable drops the footer line. IBM Plex Mono is served as `Satzspiegel Mono` because a subset may not use the OFL Reserved Font Name. |
| `pandoc/` | `templates/satzspiegel.html`, `defaults/satzspiegel.yaml` and `satzspiegel-gfm.yaml`, `filters/satzspiegel.lua`. `make install` copies them into Pandoc's user data directory and writes a `satzspiegel-local.yaml` pointing at `~/.local/share/satzspiegel`. |

| `index.html`, `readme-review.html` | The README rendered by `make readme`: the GitHub Pages home page, and the README as a light review edition (no fonts) that the README links to as its own demonstration. Regenerate after editing the README and commit both. |
| `docs/usage.md` | The reference: every defaults file, variable, class, the review edition in detail, mail advice, typefaces, licences, repository layout. The README is the story and links here; reference material goes here, not in the README. |
| `docs/showcase.md`, `scripts/themes-shot.js`, `scripts/review-shot.js` | The short document behind the README's screenshots: `docs/img/themes.png` (both themes side by side) and `docs/img/review.png` (the Patina review edition with comments added in the browser). `make showcase` renders the four pages; the scripts shoot them with Playwright and need the static server. |

No package manager, no build step for the CSS. `make check` is the test suite (contrast, renders, embed assertions, extractor) and `.github/workflows/smoke.yml` runs it on a checksum-pinned Pandoc with the checkout action pinned by commit; it also fails if the committed `index.html` is stale. Review editions are built only from the working tree (`REVIEW` in the Makefile); every `<` in the annotation payload is escaped as `\u003c` and merged items are shape-validated, both in the layer and in `scripts/annotations.mjs`.

## Commands

```bash
brew install pandoc               # once; Pandoc 3.11 was used for development
make install                      # Pandoc template, defaults, filter, plus CSS and fonts for offline use
make sample                       # renders sample.md into build/ (patina, archive, gfm, embedded)
make                              # lists the targets
make check                        # contrast, every render, embed assertions, extractor; what CI runs
make verify-fonts                 # fonts/ against fonts/SHA256SUMS
make review                       # review editions of sample.md and the essay into build/
make readme                       # README.md -> index.html and readme-review.html
make showcase                     # docs/showcase.md in both themes, for docs/img/themes.png
make examples                     # examples/*.md in both themes into build/examples
make site                         # the whole GitHub Pages site into _site/
make serve                        # python static server on http://127.0.0.1:8765; the browser pane's launch.json is local and git-ignored
make fonts                        # re-fetch WOFF2 subsets and licences
pandoc doc.md -d satzspiegel -o doc.html                 # after make install
pandoc doc.md -d satzspiegel -V theme=archive -o doc.html
pandoc doc.md -d satzspiegel-local --embed-resources -o doc.html
```

The defaults files use `to: html`, not `html5`: Pandoc appends the writer name to a bare template name, so `html5` would look for `satzspiegel.html5`. They set no `theme` variable, because a variable in a defaults file outranks `-V` on the command line.

Never build a self-contained file from the hosted defaults (`-d satzspiegel-review` with `--data-dir=pandoc`) while GitHub Pages is not live: Pandoc cannot fetch the hosted stylesheet and script, only warns, and writes a file with no styling and no review layer. The Makefile's `REVIEW` recipe embeds from the working tree, and `assert-embedded` fails the build if a hosted `.css` or `.js` reference survives or no script was embedded. Test review editions opened from `file://`, not only over http, because that is how reviewers open them.

Verification is visual: render `sample.md`, serve the repo root, and screenshot with Playwright (the `playwright-skill` bundle has it). To prove the fonts load, count `.woff2` entries in `performance.getEntriesByType('resource')` or read `FontFace.status` from `document.fonts`; do not use `document.fonts.check()`, which returns true even when no face has loaded and hid a broken font set once. A Patina page should fetch 3 to 6 Latin files.

## Architecture

**Two themes over one component layer.** Patina's tokens sit on bare `.md`, so `class="md"` alone is Patina; Archive overrides the same custom properties. Components read only tokens. The theme devices live in the `md.layout` layer: Patina becomes a two-column grid (measure plus a 24ch notes column, footnotes in column 2) inside `@container md-host (min-width: 86rem)`, but only when the document has footnotes (`:has(> .footnotes)`), so a document without notes keeps one centred column; Archive keeps a 6ch left margin for section numerals drawn by `h2::before` from a counter.

**The host wrapper is required.** `.md-host { container-type: inline-size }` is what every container query measures. Without it the marginalia, the bleed, the stacked table and the two-column definition list never engage. The Pandoc template emits it.

**Cascade layers.** `satzspiegel.css` declares `md.tokens … md.code-fallback, md.layout, md.print`; the code module adds `md.code`, which is appended after `md.print` and so wins over the fallback. Host styles outside any layer beat everything.

**The measure is padding on the container, not `max-width` on children.** `ch` resolves against each element's own font size, so a per-child cap gives one left edge per type size. Blocks that may break out (`figure`, `.md-table-scroll`, `.md-code`, `pre`, `.sourceCode`) take a negative inline margin under a container query. In Patina's grid mode they stay in column 1 instead.

**Rhythm.** `--md-rhythm` is one line of leading; every vertical space is a multiple of it. New spacing must be expressed in it.

**Pandoc markup the component layer catches.** Footnote refs are `a.footnote-ref > sup`; the notes section is `section.footnotes` opening with an `hr` that is hidden; task lists put the checkbox inside `label`, and loose lists inside `p > label`; alerts are `div.note` with `div.title`; tables carry `style="text-align: right"`; code is `div.sourceCode > pre > code > span` per line with an anchor per line, and `numberLines` adds `pre.numberSource`. The line spans stay inline because Pandoc separates them with newlines; only the hand-authored `.md-code--numbered .md-line` markup, which has no newlines, is display block. The GFM shapes (remark, markdown-it) are supported alongside.

**The review edition** keeps a pristine copy of the page's own HTML at load and, on save, rewrites only the annotation block inside that string, so the UI never leaks into the saved file. Anchoring is by TextQuoteSelector against a whitespace-collapsed text index of `.md`, with the DOM left untouched (highlights come from `CSS.highlights`). Reviewers' replies are annotations whose `target` is the parent's id. Test it with Playwright: select text via a Range, click the Comment button, save, capture the download, reopen it and count anchors.

## Design rules that constrain every change

- One spot colour per theme, used to encode structure. Alerts are single-forme by default; the five tones are behind `md--tinted-alerts`.
- Rules are hairlines and horizontal. No vertical rules in tables, no four-sided boxes, no filled cards. Code blocks sit between two rules.
- Three heading sizes; h4 to h6 differ by weight, italic and small caps.
- Bold is 650. Six syntax roles, one forme. Every text colour at least 4.5:1 on its paper; recompute with a contrast script before changing an ink value.
- Opt-in classes exist so the default stays quiet: `md--indent`, `md--justified`, `md--tinted-alerts`, `md--nocode`, `md-table--*`, `md-ol-nested`, `md-dl-columns`, `md-pull`, `md-runin`, `md-code--numbered`, `md-code--wrap`.

## Publishing

Published on 11 September 2026 as `yobu/satzspiegel`, public, MIT plus OFL fonts. GitHub Pages is deployed by `.github/workflows/pages.yml`, which runs `make site` and publishes `_site/` on every push to `main`, so the hosted site is the built site (usage guide, examples, plates, review sample included) and every hosted URL the defaults files, README and usage guide point at comes from `make site`. The template links `fonts.css` only when `fonts-css` is set. `v1.0.0` is tagged and released; jsDelivr serves tags at `https://cdn.jsdelivr.net/gh/yobu/satzspiegel@1/…`. CI (`smoke`) runs `make check` on every push and fails if the committed `index.html` is stale, so run `make readme` before committing a README change. `docs/show-hn.md`, `.claude/`, the generated canvas artboards and every `*.annotated.html` are git-ignored on purpose. Commit or push only when the user asks; a release is a tag plus `gh release create` with the changelog section as notes.
