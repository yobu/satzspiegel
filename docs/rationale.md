# Typographic, book and web design awards 2025/2026
## …and a Markdown component set derived from them

Compiled 10 September 2026. Two parts: an award survey (who won what), then a
component set for Markdown rendering derived from what the juries actually
rewarded.

A note on provenance before anything else. Everything in Part 1 and Part 2 is
reported fact from the awarding bodies or trade press. Everything in Part 3 and
Part 4 — the extracted principles, the palettes, the scales — is **my
derivation**. No jury published a colour palette. The palettes below are built
from the register the winners work in, not sampled from their pages.

# Part 3 · What the juries actually rewarded

Reading across all eleven competitions, seven principles recur. These are the
transferable part. Everything in Part 4 follows from them.

**1 · Type area before typeface.** The Buchkunst criteria lead with
*Satzspiegel* — the block of set text and its relationship to the four margins
— then legibility, then the book as a physical object. Typeface choice is
downstream. The commonest Markdown-rendering failure is the reverse: a
carefully chosen face poured into an unconsidered column.

**2 · Small is the professional register.** Nine of the fourteen Leipzig
winners are under 230 mm on the long edge; one is 50 × 68 mm. Small format means
short measure, small type, and margins doing the work. Almost every Markdown
renderer defaults to type that is too large for its measure.

**3 · One spot colour, used structurally.** The winning register is ink plus a
single second forme, deployed to *encode structure* — a numeral, a rule, a
reference mark — not to decorate. Never two accents.

**4 · Rules are hairlines, and horizontal.** Across the book winners: no
vertical rules, no boxes around content, no fills. Where a rule appears it is a
hairline doing a structural job. The web's habit of framing every table cell
and wrapping every note in a tinted card has no counterpart in any of this
work.

**5 · Depth by style, not by size.** Book hierarchies are shallow. Where more
levels are needed they come from italic, small caps, weight and indent — not
from a six-step size ramp. Markdown gives you six heading levels; the awards
suggest using three.

**6 · Variable fonts with optical sizing are the new baseline.** TDC72's Best
of Type Design went to a variable font. Klim's first retail variable font
shipped with optical sizes in 2025. The TDC type categories are now organised
*by axis count*: single style, single axis, multiple axis, superfamily. This is
now how the field thinks about type.

**7 · Legibility under load.** The €10,000 Preis der Stiftung Buchkunst 2026
went to a children's crisis-guide. The Jan Tschichold Award went to a duo whose
stated position is that typography is a cultural and political fact and design
is research. Both prizes reward type that has to *work* — which is exactly the
brief for a Markdown renderer.

## 4.2 The structural decision — and the trap in it

Principle 1 as CSS. The column is made by padding the container, not by capping
each child:

```css
.md { padding-inline: max(0px, calc((100% - var(--md-measure)) / 2)); }

@media (min-width: 62rem) {
  .md > figure,
  .md > .md-table-scroll,
  .md > .md-code,
  .md > pre { margin-inline: calc(var(--md-bleed) * -1); }
}
```

The obvious version of this is `max-width: 68ch` on every child. **Don't.**
`ch` resolves against the *element's own* font size, so an `h2` at 1.563em
gets a column roughly 56% wider than a paragraph's — and a page ends up with
three or four different left edges, one per type size. It is subtle enough to
survive review and obvious enough to look wrong.

Resolving the measure once, on `.md`, at body size, gives every block one true
left edge while keeping `ch` adaptive to whichever face actually loads. Figures,
tables and code then borrow from the margin with a negative inline margin,
guarded by a width query so there is no overflow when there is nothing to
borrow.

The mistake is worth documenting because it is invisible in a single-element
test and only appears once a real document with mixed sizes runs through.

## 4.3 Component inventory

Every element a Markdown pipeline can emit, and the decision made for each.

### Headings

| Level | Treatment | Rationale |
|---|---|---|
| `h1` | Ratio³ (`letter` 2.441em, `grid` 3.052em). Once per document. Space below only. | Title, not a section |
| `h2` | Ratio². Extra space above; `grid` adds a hairline over. | The section |
| `h3` | Ratio. Last size step. | The subsection |
| `h4` | Text size, weight 650 | Principle 5: style, not size |
| `h5` | Text size, italic | " |
| `h6` | 0.9em, small caps, muted ink | " |

Space above always exceeds space below, so a heading reads as belonging forward.
`h4.md-runin` folds a heading into the following paragraph as a run-in — the
book device Markdown cannot express, available as an opt-in class.

### Lists

| Concern | Decision |
|---|---|
| Marker position | `outside`, hanging in the indent, so the text edge stays true |
| Ordered figures | `tabular-nums lining-nums` on `::marker` — so `9.` and `10.` align |
| Nested unordered | disc → en dash → middle dot |
| Nested ordered | decimal → lower-alpha → lower-roman |
| Tight vs loose | Detected via `li:has(> p)`; loose lists get half-rhythm separation, no class needed |
| Task lists | Control pulled into the hanging indent; checked items drop to muted ink |
| Legal numbering | `.md-ol-nested` gives 1 → 1.1 → 1.1.1 via counters |
| Definition lists | Full support, plus `.md-dl-columns` for a two-column glossary at container width |

Ordered-list figure alignment is the most common single defect in default
Markdown rendering. It is one `::marker` declaration to fix.

### Tables

Principle 4, applied literally.

| Concern | Decision |
|---|---|
| Vertical rules | None. Ever. |
| Horizontal rules | Three maximum: over the head, under the head, under the body. Interior row rules at 55% rule opacity. |
| Zebra striping | **Off by default.** Available as `.md-table--zebra`. |
| Caption | `caption-side: top`. Above the table, set like a figcaption. |
| Numeric columns | GFM's `---:` emits `align="right"`; the stylesheet catches that and applies tabular lining figures automatically. `.md-table--numeric` does the whole body. |
| Header style | Weight 600 sentence case; `grid` uses small caps, not all caps |
| Overflow | `.md-table-scroll` wrapper; `.md-table--stack` folds rows into labelled stacks under 30rem |
| Footer | `tfoot` drops a step in size and to muted ink, no top rule |
| Density | `.md-table--compact` halves row height for reference tables |

### Quotations

`letter` indents on both sides at 0.94em, no rule — the book solution.
`grid` and `screen` use a left rule, because that is a genuine screen
convention rather than a mistake. `cite` and `.md-attrib` render as an
em-dash-led attribution line. `.md-pull` gives a measure-breaking pull quote
for the one place per document where scale should carry the argument.

### Code — the optional module

Three levels of removal, increasing in severity:

1. **Don't load `markdown-code.css`.** Fenced blocks fall back to a quiet set
   block: mono face, hairline rules above and below, no fill, no colour. This is
   how a book sets code, and for documents where code is illustrative rather
   than operational it is the better choice.
2. **Add `.md--nocode`.** Fenced blocks are hidden entirely; inline code
   reverts to italic in the text face.
3. **Strip fences at build time.** Nothing to style.

With the module loaded: six syntax roles only — text, comment, keyword, string,
number, name — because past six the block stops being text and becomes
decoration. `grid` runs code in ink alone plus the spot for names, as a single
forme would on press. Line numbers are opt-in, tabular, right-aligned and
`user-select: none` so copy stays clean. The filename head is set as a caption,
not as window chrome. Class names cover Prism, highlight.js and Shiki.

### Everything else

| Element | Decision |
|---|---|
| `a` | Underline 0.075em at 0.16em offset, spot at 55%, ink-skip on. Colour is the hover state; the underline is the affordance. |
| `strong` | 650, not 700 — variable text faces muddy at full bold in running copy |
| `hr` | A typographic pause, not a border. `letter` sets a fleuron; `grid` a full-measure ink hairline; `screen` a rule hairline. |
| `figure` | `figcaption` at 0.86em muted, `.md-fig-num` for the numeral in ink. `grid` adds a hairline above the caption. |
| Footnotes | References in spot with tabular figures, no underline — apparatus, not links. Note block separated by hairline, dropped a step, muted. `:target` highlight on jump. |
| Alerts | Single vertical rule plus a label. No fill, no icon, no card. Tone is one custom property per severity so projects can add their own. |
| `kbd` | Mono, hairline border with a 2px bottom, sunk background |
| `abbr[title]` | Dotted underline at 0.18em offset |
| Inline `code` | Lives in the **text** layer, not the code layer, so it survives when the module is dropped |
| Print | Measure released, 10.5pt, `break-after: avoid` on headings, `break-inside: avoid` on figures/tables/code, URLs appended to links |
| Justification | `.md--justified` opt-in with `hyphens: auto` and `hyphenate-limit-chars: 6 3 3`. Off by default: unhyphenated justification is what juries penalise, not justification. |

## 4.4 Rhythm

One unit, derived rather than declared:

```css
--md-rhythm: calc(var(--md-leading) * var(--md-size));
```

That is one full line of leading — 30.8px in `letter`, 24px in `grid`. Tying it
to `--md-size` rather than `1rem` means a fluid base size re-rhythms the
document as it scales.

Every vertical space in the set is a multiple of it: `0.25` between list items,
`0.5` after a heading, `1` between paragraphs, `2` before an `h2`. Change
`--md-leading` and the whole document re-rhythms.

## 4.5 Integration

```html
<link rel="stylesheet" href="markdown.css">
<link rel="stylesheet" href="markdown-code.css"><!-- optional -->

<article class="md" data-md-theme="letter">
  <!-- rendered markdown -->
</article>
```

The stylesheet uses `@layer`, so host styles win by default unless the host also
layers. Container queries are used for the stacking table and the two-column
definition list, so the parent needs `container-type: inline-size`.

Two things your pipeline should emit to unlock the full set:

- wrap tables in `<div class="md-table-scroll">`
- for `.md-table--stack`, put `data-label` on each `td`

Both are single-line plugins in remark, markdown-it and Kramdown.

## 4.6 What I would still verify before shipping

- **Face licensing.** The `ideal` column in 4.1 lists licensed faces. The
  named substitutes are the open-source stand-ins actually loaded in the
  specimen; they are close in register, not identical.
- **Old-style figures in `letter`.** Literata has them, but check that your
  build does not subset the `onum` feature out.
- **`hanging-punctuation`.** Safari only, at time of writing. Harmless
  elsewhere, but do not rely on it for alignment.
- **The `screen` dark palette against your host page.** Dark themes are the
  one place where a component set cannot be judged in isolation.
