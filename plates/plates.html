Table

  1. Caption above. A table is read top down; its title belongs where reading starts. Set like a figure caption, muted, one step down.
  2. Three rules at most. Ink hairline over the head, under the head, under the body. Grid sets heads in small caps at 550, not all caps: quieter at the same emphasis.
  3. No vertical rules, no fills. Columns are separated by a 2-character gutter and nothing else. Interior row rules exist at 55 % of the rule colour so they read as guides, not as structure. Zebra striping is opt-in only.
  4. Numeric columns right-aligned. GFM's ---: emits align="right"; the stylesheet keys off it and needs no class.
  5. Tabular lining figures. Applied automatically to right-aligned cells, so 2.5 and 18.7 share a decimal column without a decimal-align property the browser does not have.
  6. Foot drops a step. No rule above it, muted ink, 0.94 em. A source line, not a totals row.
  7. Compact. Row height 0.22 of the rhythm instead of 0.36, gutter 1.4 ch. For tables read by lookup, not in sequence.

Table type is 0.94 em at leading 1.4: a step smaller than text, tighter than text, because rows are scanned rather than read.

  2. Tabular lining on the marker. One declaration on ::marker. Every figure takes the same width, so 9 sits under the 0 of 10 and the two markers read as a column.

  8. Task control in the indent. The checkbox takes the marker's place. Checked items drop to muted ink, so state reads as tone rather than strike.
  9. Loose lists detected. li:has(> p) gives half the rhythm between items, matching GFM's own tight-versus-loose model.
  10. Definition lists in two columns. A container query above 34 rem; terms in a 22-character column, aligned to the first baseline.

Plate 6 Heading ladder

Six levels, three sizes. The same ladder in each theme, so the ratio and the style devices can be compared directly.

Headings

  1. h1 at ratio³. Once per document; a title, not a section. Space below only. Letter drops to weight 500 so the size carries it; Grid jumps to 3.05 em, the one big step the register allows.
  2. h2 at ratio². The section. Two rhythm units above, half below, so it belongs to what follows. Letter sets it italic; Grid rules over it in ink.
  3. h3 at ratio. The subsection and the last size step. One and a half units above.
  4. h4 at text size, weight 650. A label on a paragraph, which is what most authors mean by a fourth level.
  5. h5 at text size, italic. Still reads as a heading with no size change at all; slope carries the signal.
  6. h6 at 0.9 em, small caps, muted. Exists so that the level never falls back to something worse.
  7. Run-in. h4.md-runin folds the heading into its paragraph with a full stop. The book device Markdown has no syntax for.

The lead paragraph after h1 is 1.15 em: italic in Letter, weight 450 in Grid, plain in Screen.

Alerts

  1. A label, not an icon. Weight 650 at 0.92 em in the tone. The word does the work an icon would, and it survives print and copy.
  2. No fill, no card. Body text stays in ink at text size; only the rule and the label carry the severity. The block is 1.4 ch in from the rule.
  3. One vertical rule. The exception to the horizontal rule. It is a screen convention, like the quotation bar, and it is 3 px so it reads as a mark rather than a border.
  4. Five tones. Note takes the spot; tip, important, warning and caution take fixed hues with dark counterparts in Screen. This is the one place the set has more than one accent.
  5. Single forme. Tones collapse to muted ink; note alone keeps the spot, because a note is structural and the rest are editorial. Severity is the word.
  6. The cost. Warning and caution no longer differ at a glance. Whether that matters depends on whether the document is read or scanned.

Recommendation: ship B as the default and keep A behind a class. A document with five colours of alert has five accents, and the rule says one.

Plate 8 Decision 1, paragraphs in Letter

Spaced with no indent, or indented with no space. The same four paragraphs, a list and a heading, so the seam where the models meet is visible.

ASpaced, no indent. As shipped. One rhythm unit between paragraphs.

BIndented, no space. .md--indent: indent of one line of leading on p + p only.

Recommendation: B, as the Letter default. The theme exists to be the book register, and the space-between model is the single thing that makes a page read as a web page before a word is set. The indent is derived, not declared: one line of leading, 1.62 em, so it moves with the rhythm.

The objection is that Markdown interleaves paragraphs with lists, tables and code, where a book would not. B answers it by indenting only a paragraph that follows a paragraph. After a heading, a list or a table the paragraph stays flush with full rhythm space, which is book practice too, and a document of short blocks degrades into A without any seam.

Grid and Screen keep A. They are screen registers, and the web default is correct there.

Temperature is not the problem: A and B are within a tenth of each other on every value, and the cool paper is what separates the block from a #000 or #1E1E1E host. On a neutral host, B disappears into it. Keep #101317.

Weight is a real problem, but it is the mixing, not the spot. Mixing a light spot into dark paper at 55 % halves its contrast; the same rule on a light theme mixes a dark spot into light paper and stays dark. The fix is one declaration scoped to the dark state: underline at 85 %. The footnote marks and the quotation rule use the spot at full strength and read at 7.7 : 1, comfortably above the 4.5 : 1 that text requires.

One value stays marginal in both: faint ink at 4.1 : 1 is used for list markers at 0.85 em. It passes for graphics, not for text. Raising it to #7D8493 would give 4.8 : 1 at no visible cost.

Plate 10 Decision 3, the section rule in Grid

Six short sections, the worst case for a ruled heading. With the ink hairline, without it, and with the hairline dropped to the rule colour.

AInk hairline over every h2. As shipped.

BNo rule. Space and size alone.

CHairline in the rule colour, #C9C9C9.

Recommendation: keep A. The rule is not decoration; it is what the theme is. The Spector register signals a section with a hairline the full measure wide, and without it Grid becomes a smaller Screen.

With many short sections the rules do read as stripes, but the stripes are the structure: six rules for six sections is an honest count, and each one marks a place the eye can return to. B loses the grid and gains nothing but quiet. C keeps the position and loses the meaning; a grey rule under a black heading looks like a border that failed to load.

One mitigation is already in the stylesheet: a rule immediately after hr is suppressed so nothing draws twice. If the same page had twenty sections the answer would be to nest them, not to unrule them.

Plate 11 Decision 4, the pause in Letter

Two section breaks in running text. The shipped fleuron, a short centred rule, blank space, and an asterism the face actually carries.

AFleuron ❊, as shipped.

BShort centred hairline, 5 ch, faint ink.

CBlank: two rhythm units and nothing else.

DAsterism ⁂, set from Literata itself.

Recommendation: D, the asterism. A is disqualified by a finding rather than a preference: Literata does not carry U+274A, so the fleuron is set from whatever dingbat font the system supplies, at whatever weight and baseline it has. It is a foreign glyph on every page, and it differs by platform. Literata does carry the asterism, so D is the same ornament idea set from the same face, and it weighs the same as the text around it.

C is the classical book answer and fails on screen for the reason it works in print: blank space is a break only if you can see both sides of it, and at the edge of a viewport it is invisible. B is the honest screen answer and reads correctly, but it is a rule, and Letter is the theme that has none; a rule here makes it the odd device out. D marks the pause with type.

If the face changes, check the glyph first. The rule for ornaments is the rule for everything else in this set: it must come from the text face or not at all.

Code

  1. The filename is a caption. Mono at 0.78 em, muted, above the block like a figure caption. Not a window-chrome bar, and no traffic lights.
  2. Language label right, faint. Metadata, so it takes the lowest ink.
  3. Line numbers opt-in. Tabular, right-aligned in a 3.5-character gutter, and unselectable so a copied block carries no numbers.
  4. The marked line. The spot at 12 %, the one tint in the whole set. It is the spot's own colour, so it is structure, not a second accent.
  5. Comment. Faint ink, italic. Finding: 3.3 : 1 on white and 3.0 : 1 on Letter's sunk paper, below the 4.5 : 1 that text needs. A comment is text. Proposed: muted ink, still italic, at 7.2 : 1.
  6. Keyword. Weight 550 in Grid, where the keyword is ink and the weight is the only difference from text.
  7. Six roles, no more. Text, comment, keyword, string, number, name. Prism's property and punctuation fall to text and muted ink, so a CSS block is mostly ink with names in the spot.
  8. Number. Tabular lining figures on the whole block, so aligned columns of values stay aligned.
  9. Name. Selectors, functions, tags and class names take the spot: the same job the spot does for a list marker.
  10. Diff, as shipped. Green and red tints at 12 to 14 %, and the span is inline, so the tint stops at the last character. Two fixed hues that are not the spot.
  11. Diff, proposed. Rows made block so the tint runs the row, and Grid keeps its single forme: added lines take the spot tint, deleted lines the sunk paper with a strike. Letter and Screen may keep the hues.
  12. Inline code in the text layer. Grid draws a hairline around it, the only box in the set. It marks a change of alphabet rather than a container, and it survives when the module is dropped.
  13. A defect in the shipped numbering. Each numbered line is a grid with two columns, so every token span and text run becomes its own grid item and the line shatters into a column. It works only when a line is one span. The specimen has the same fault. Proposed: the line stays a block and the counter is an inline block of gutter width. Three declarations.
  14. The box. Grid rules a hairline on all four sides of a block, the only four-sided box in the set. Rule three says none. The fallback already sets code between two horizontal rules; proposed: Grid does the same with the module loaded, as in block B.

Without this module a fenced block is a quiet set block in the mono face between two hairlines. That fallback is deliberate and often the better choice.

Letter is the book register, and a book sets code as a second forme: ink plus the one colour the text already uses. Four hues on cream pass contrast and fail the rule. The two-forme mapping is the Grid mapping with cinnabar in place of ultramarine, so nothing new is invented; the keyword goes to weight and the name to the spot, and the block reads as the same document as the prose around it.

Screen is the editor register, and a chromatic palette is what its readers parse code by. Four hues on dark at 8.8 to 11.1 : 1 is the strongest legibility in the set, and the pink and periwinkle are analogous to each other, so the block still has one temperature. Keep it, and treat the code block as the one place Screen is allowed a second forme, because on screen that is the convention the readers arrive with.

Comments are the real defect. Faint ink italic at 0.845 em is decoration-grade contrast on text that explains the code. Muted ink keeps the italic and the recession and passes in all three.

Gaps in the class map, found by running a real highlighter. The module claims Prism, highlight.js and Shiki. Shiki emits inline styles by default and CSS variables under its css-variables theme; the module defines none of those variables, so Shiki output is unstyled. highlight.js emits hljs-attribute, hljs-selector-class, hljs-built_in and hljs-variable, none of which are mapped. Candidate rules for both sit at the end of the plates stylesheet.
